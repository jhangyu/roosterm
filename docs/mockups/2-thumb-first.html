Thumb-first mobile

Every frequent action lives in the bottom third of the screen. Tabs are a swipeable pill dock, the new-tab button is a FAB under the thumb, and the special-key bar sits directly above the on-screen keyboard. The desktop layout is the same stack, scaled up: tabs and keys stay on the bottom edge.

Trade-offs of this direction

  • One-handed use, but less terminal height. The tab dock (65px) and key bar (66px) take about 130px. With the keyboard open, a 390×844 phone shows about 16 terminal rows.
  • One layout on every platform, but bottom tabs are unusual on desktop. Desktop users expect tabs at the top. Bottom tabs keep one component tree and one muscle memory, at the cost of first-use surprise.
  • Large targets, fewer visible tabs. 48px pills fit about 2.5 tabs on a phone. More tabs need a horizontal swipe, and long names truncate sooner than in a dense tab strip.

Thumb rules

  • 56px fields and a 56px full-width button, all below the screen midline.
  • Left: default state. Right: error state. The error shows inline above the fields, not as a toast at the top.
  • Desktop: the same card, centered at 400px width.

Reach map

  • The top header holds only rare actions (keyboard toggle, menu). Host status stays visible.
  • Tab dock: swipe the pills left or right to switch. 48px tall, 8px gaps.
  • New tab: 56px FAB at the right-thumb position.
  • Key bar: 52px keys with 6px gaps. It scrolls sideways when more keys are added. Ctrl C is red because it interrupts.
  • Keyboard closed: the dock and key bar move down to the home indicator, and the terminal gets the 252px back.

Behavior

  • Close tab is primary: an exited shell has no further use. Restart is secondary.
  • A non-zero code swaps the green seal for a red one and states the code in the title.
  • The key bar hides: no process receives keys.
