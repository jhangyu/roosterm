Roosterm · Mockup 1 — Dense Workbench

Desktop-first, IDE-panel density: 88px of chrome on a 720px viewport, the rest is terminal. Fluent 2 visual language, Material 3 corner scale, light theme.

Radius — M3 shape scale

corner-none → terminal, bars0px
corner-extra-small → tabs, buttons, inputs, keys4px
corner-small → app frame, banners, list, options8px
corner-medium → dialog, spec cards12px
corner-large → (reserved: sheets)16px
corner-extra-large → phone frame only28px
corner-full → status pills, avatar9999px

Type scale — Fluent 2

caption2 · status bar, badges10/14
caption1 · chrome default (tabs, menus)12/16
body1 · dialogs, forms14/20
subtitle2 · section heads16/22
subtitle1 · dialog title20/28
title3 · login24/32
terminal cell (mono)13/18

Sans: Segoe UI → system. Mono: Cascadia Mono → Consolas → SF Mono → Menlo. Motion: 150/200ms, curveEasyEase. Elevation: Fluent shadow4/16/64.

Trade-offs of this direction

  • + Max terminal area: 32px title + 34px tabs + 22px status = 88px chrome; at 1280×720 that is ~160×34 cells at 13px. − 12px chrome text and 24px icon buttons are below touch size, so phone needs a separate layout (screen 4), i.e. two chrome variants to maintain.
  • + Familiar to power users: flat IDE tabs, status bar with latency/size/encoding, keyboard hints. − Feels utilitarian; less approachable for a first-time or mobile-first user.
  • + Status is ambient, not modal: disconnects and exits render as a thin bar/strip that never covers output. − Thin bars are easy to miss on a large monitor; relies on tab badges and status-bar color as a second signal.
