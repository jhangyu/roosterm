## Parking-lot (not fixed; for the user)
Review follow-ups:
- should-fix: host/internal/web/login.go:30 reads only the first `roosterm_device` cookie; a sibling-subdomain page can plant a same-name cookie sent first and restore the owner lockout. Fix: check every cookie from r.CookiesNamed, or rename with the `__Host-` prefix and Path=/.
- nit: host/internal/web/server.go:30 web.New accepts a nil DeviceLimiter, which panics on the first login with a valid device cookie.
Residual risks by design: a new or cleared device can still be locked out during an attack; a stolen device cookie gives a second 5-per-60 s budget until passwd + restart; old password and sessions work until restart after passwd; Android does not pass POST navigations or iframes to the check (needs script on roosterm's own origin); an SSO proxy on another origin is blocked in the app; a Host-rewriting proxy with old browsers fails closed.
Low/Info scan findings:
- Session cookie has no `__Host-` prefix (sibling subdomain can force logout).
- Logout whose save fails returns the token after restart.
- config.toml mode not checked on load.
- Atomic write follows a planted .tmp symlink (needs write access to the config dir).
- Username comparison leaks length; no session idle timeout.
- An open WebSocket survives logout or expiry until restart.
- No HTTP read/idle timeout (pre-login connections can be held).
- No security headers (CSP, frame-ancestors, nosniff, Referrer-Policy).
- Logged-in JSON has no Cache-Control: no-store.
- /tmp/tmux-<uid> swarm socket dir trusted without owner/mode check.
- Tab labels allow Unicode format characters (spoofing).
- Post-login error bodies show host paths and hc messages.
- GET /api/swarms deletes dead socket files.
- Android backup of the WebView cookie not disabled.
- shadcn CLI listed as a runtime dependency (minimatch advisory, not bundled).
- Recent-folder list not cleared on logout.
- `npm ci` runs install scripts.
- systemd units have no sandboxing (by design: the service provides a full shell).
